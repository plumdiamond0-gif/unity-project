코루틴

1. MonoBehaviour 생성자 사용 ❌ (가장 큰 문제)
public ObjectPool(GameObject gameObject, int count)
이건 사용하면 안 돼.
MonoBehaviour는 new ObjectPool()로 생성하는 클래스가 아니라 Unity가 AddComponent나 씬 로드 시 생성하기 때문이야.

국내 대학(청강문화산업대학교, 동양대학교, 한국공학대학교 등)과 게임회사 신입 채용 면접에서 
공통적으로 보는 평가 요소는 상당히 비슷합니다.

아래는 실제 면접 기준을 종합하여 정리한 평가 지표와 일반적인 비중입니다.

    평가항목                      비중              평가 내용
    프로그래밍 실력        35~45%        C++, C#, 자료구조, 객체지향, 알고리즘 이해도
    포트폴리오 완성도   25~35%       본인이 제작한 게임의 수준, 기능 구현, 기술적 난이도
    기술 설명 능력            15~20%           자신이 만든 코드를 논리적으로 설명하는 능력
    문제 해결 능력           10~15%           버그 해결 경험, 최적화 과정, 개발 과정에서의 판단
    협업 및 태도                5~10%           Git 사용, 팀 프로젝트 경험, 커뮤니케이션

가장 중요한 것은 '직접 만들었는가'

    면접관들은 거의 이것부터 확인합니다.
    예를 들어
        "이 캐릭터 이동 시스템은 어떻게 구현했나요?"
        "왜 State Pattern을 사용했나요?"
        "충돌 처리는 Update에서 하나요? FixedUpdate에서 하나요?"
    이런 질문에 바로 답하지 못하면
        "AI나 인터넷에서 가져온 코드인가?"
    를 의심하게 됩니다.

포트폴리오에서 높은 점수를 받는 요소

★★★★★ 구현 난이도

    FSM(State Machine)
    AI
    Path Finding
    Inventory
    Save/Load
    Network
    Object Pool
    UI 시스템
    이런 시스템을 직접 구현했다면 좋은 평가를 받습니다.

★★★★☆ 코드 품질

    예를 들어
    Player
    Enemy
    GameManager
    InputManager
    SoundManager
    처럼 역할이 잘 분리되어 있는지,

    SOLID 원칙
    객체지향 설계
    재사용 가능한 코드
    등을 봅니다.

★★★★☆ 문제 해결 과정

    면접에서 자주 나오는 질문입니다.
    개발하면서 가장 어려웠던 점은?
    어떻게 해결했나요?
    다시 만든다면 어떻게 개선하시겠습니까?
    단순히 "완성했다"보다 문제를 분석하고 해결한 과정을 설명하는 것이 높은 평가를 받습니다. 
---

합격권 포트폴리오의 특징

    보통 좋은 평가를 받는 포트폴리오는 다음과 같은 구성을 갖습니다.

    1~2개의 완성도 높은 게임
    Git을 통한 버전 관리
    코드 구조도 또는 클래스 다이어그램
    주요 시스템 설명 문서
    구현 영상(3~5분)
    핵심 코드 설명 자료
    개발 중 발생한 문제와 해결 과정 정리
