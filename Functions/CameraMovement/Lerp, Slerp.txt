`Lerp`와 `Slerp`는 둘 다 **두 값 사이를 부드럽게 보간(Interpolation)** 하는 함수이지만, **보간하는 방식**이 다르다.

| Lerp                                        | Slerp                                    |
| ------------------------------------------- | ---------------------------------------- |
| Linear Interpolation(선형 보간)                 | Spherical Linear Interpolation(구면 선형 보간) |
| 직선 경로로 보간                                   | 원호(구면) 경로로 보간                            |
| `Vector3`, `float`, `Color` 등 일반적인 값에 많이 사용 | `Quaternion`(회전)에 주로 사용                  |
| 계산량이 적음                                     | 계산량이 조금 더 많음                             |

---

## Lerp

```csharp
Vector3.Lerp(a, b, t);
```

현재 값에서 목표 값으로 **직선으로** 이동한다.

예를 들어

```text
A ●────────────● B
```

Lerp는 직선으로 이동한다.

현재 코드에서는

```csharp
_targetRotation = Vector3.Lerp(
    _targetRotation,
    Vector3.zero,
    returnSpeed * Time.deltaTime
);
```

즉,

```text
반동값

10°

↓

8°

↓

6°

↓

3°

↓

0°
```

처럼 **목표 반동값 자체를 감소**시키는 데 사용한다.

---

## Slerp

```csharp
Vector3.Slerp(a, b, t);
```

또는

```csharp
Quaternion.Slerp(...)
```

Slerp는 **원호를 따라 자연스럽게** 이동한다.

```text
      ●
   ／   ＼
 A         B
```

회전은 직선보다 **원형으로 움직이는 것이 더 자연스럽기 때문에** Slerp가 자주 사용된다.

현재 코드에서는

```csharp
_currentRotation = Vector3.Slerp(
    _currentRotation,
    _targetRotation,
    snappiness * Time.deltaTime
);
```

즉,

현재 카메라 회전이 목표 회전을 **부드럽게 따라가도록** 한다.

---

## 왜 이 코드에서 둘을 사용했을까?

사실 이 코드에서는 `_targetRotation`과 `_currentRotation`이 둘 다 `Vector3`이다.

```csharp
private Vector3 _targetRotation;
private Vector3 _currentRotation;
```

따라서 **`Vector3.Slerp`를 사용하지 않고 `Vector3.Lerp`를 사용해도 큰 차이는 없다.**

즉,

```csharp
_currentRotation = Vector3.Lerp(...)
```

로 바꿔도 대부분의 경우 비슷하게 동작한다.

다만 회전값을 다루는 시스템에서는 관례적으로 **Slerp를 사용해 더 자연스러운 회전 움직임을 표현**하는 경우가 많다.

---

### 정리

* **Lerp**: 값을 직선으로 보간한다. 이 코드에서는 **반동 목표값을 점차 줄이는 용도**로 사용된다.
* **Slerp**: 회전을 더 자연스럽게 보간한다. 이 코드에서는 **현재 카메라가 목표 반동을 부드럽게 따라가도록 하는 용도**로 사용된다.
* 현재 코드처럼 `Vector3`를 사용하는 경우에는 `Lerp`와 `Slerp`의 차이가 매우 크지는 않지만, **회전 움직임을 표현한다는 의도를 명확히 하기 위해 `Slerp`를 사용하는 경우가 많다.**
































이 부분이 이 시스템의 핵심이야. 많은 사람들이 **"둘 다 보간인데 왜 두 개를 쓰지?"** 라고 생각하는데, 역할이 완전히 다르다.

---

# 왜 Lerp와 Slerp를 나누는가?

이 시스템에는 **두 개의 회전값**이 존재한다.

```text
Target Rotation  (목표 반동)

Current Rotation (실제 카메라 회전)
```

둘의 역할을 분리했기 때문에 자연스러운 반동을 만들 수 있다.

---

## 1. Lerp는 "반동이 얼마나 남았는가"를 관리한다.

```csharp
_targetRotation = Vector3.Lerp(
    _targetRotation,
    Vector3.zero,
    returnSpeed * Time.deltaTime
);
```

여기서는

```text
반동이 점점 줄어드는 과정
```

을 계산한다.

예를 들어

```text
발사

↓

Target = 10°
```

시간이 지나면

```text
10°

↓

8°

↓

6°

↓

3°

↓

1°

↓

0°
```

즉

**반동 자체가 사라지는 과정**이다.

여기서는 카메라가 움직이는 것이 아니라

**목표값만 변한다.**

---

## 2. Slerp는 카메라가 목표를 따라가는 과정이다.

```csharp
_currentRotation = Vector3.Slerp(
    _currentRotation,
    _targetRotation,
    snappiness * Time.deltaTime
);
```

Current는 실제 카메라이다.

예를 들어

Target이

```text
10°
```

이 되었다고 해서

카메라가 바로

```text
10°
```

로 이동하면

굉장히 딱딱한 느낌이 난다.

그래서

```text
Current

0°

↓

4°

↓

7°

↓

9°

↓

10°
```

처럼

조금씩 따라간다.

즉

Slerp는

> **카메라의 움직임을 부드럽게 만드는 역할**

이다.

---

# 둘을 같이 쓰면 어떻게 될까?

시간 흐름으로 보면

### 발사 순간

```text
Target = 10°

Current = 0°
```

---

### 첫 프레임

Lerp

```text
Target

10°

↓

9°
```

Slerp

```text
Current

0°

↓

4°
```

---

### 두 번째 프레임

Lerp

```text
9°

↓

8°
```

Slerp

```text
4°

↓

6°
```

---

### 세 번째 프레임

```text
Target

8°

↓

7°
```

```text
Current

6°

↓

6.5°
```

---

### 마지막

```text
Target

0°
```

```text
Current

0°
```

둘 다 자연스럽게 복귀한다.

---

# 만약 Lerp만 있다면?

```text
Target

10°

↓

8°

↓

6°

↓

...
```

하지만

Current가 없다.

즉

카메라는

```text
10°

↓

8°

↓

6°
```

로 바로 움직인다.

움직임이 딱딱하다.

---

# 만약 Slerp만 있다면?

Target이

```text
10°
```

에서

계속

```text
10°
```

이다.

Current는

```text
0°

↓

4°

↓

7°

↓

9°

↓

10°
```

까지는 간다.

그런데

Target이 줄어들지 않으므로

영원히

```text
10°
```

에 머문다.

반동이 복귀하지 않는다.

---

# 왜 둘을 분리하는 것이 좋은가?

이 구조 덕분에 **두 가지 속성을 독립적으로 조절**할 수 있다.

* **Return Speed(Lerp)** : 반동이 얼마나 빨리 사라질지
* **Snappiness(Slerp)** : 카메라가 목표 반동을 얼마나 빠르게 따라갈지

예를 들어

```text
Snappiness ↑
Return Speed ↓
```

이면

```text
총을 쏘면

퍽!

하고 빠르게 튀지만

천천히 내려온다.
```

반대로

```text
Snappiness ↓
Return Speed ↑
```

이면

```text
천천히 올라갔다가

빠르게 원래 자리로 돌아온다.
```

즉, **'튀어 오르는 속도'와 '복귀하는 속도'를 각각 따로 조절할 수 있는 것**이 가장 큰 장점이다. 이 때문에 FPS/TPS의 카메라 반동 시스템에서는 현재처럼 목표값과 실제값을 분리하는 방식이 널리 사용된다.
