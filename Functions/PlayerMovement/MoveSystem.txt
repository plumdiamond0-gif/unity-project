
# 플레이어 이동 처리

--------------------------------------------------------------------------

## 1. 이동 방향 계산

```csharp
Vector3 MoveDir =
((transform.right * MovementX) +
(transform.forward * MovementY)).normalized;
```

### 기능

입력값(MovementX, MovementY)을 플레이어가 바라보는 방향을 기준으로 월드 좌표의 이동 방향으로 변환한다.

* `transform.forward` : 전진/후진
* `transform.right` : 좌우 이동

두 벡터를 더해 최종 이동 방향을 만든다.

transform.right * MovementX
transform.right는 플레이어의 오른쪽 방향 벡터이다.
예를 들어 플레이어가 북쪽을 보고 있다면
transform.right = (1, 0, 0)

이라고 생각할 수 있다.

여기에 입력값을 곱하면

MovementX = 1  → (1, 0, 0)   // 오른쪽 이동
MovementX = -1 → (-1, 0, 0)  // 왼쪽 이동
MovementX = 0  → (0, 0, 0)   // 좌우 이동 없음

즉, 입력값이 방향 벡터의 크기와 방향을 결정한다.

### 장점

* 플레이어가 어느 방향을 바라보더라도 입력 기준이 자연스럽게 유지된다.
((((((((((((((
뜻은 WASD의 의미가 항상 플레이어 기준으로 유지된다는 것이다.

예를 들어,

플레이어가 북쪽을 보고 있을 때

W → 북쪽으로 이동
D → 동쪽으로 이동

플레이어가 동쪽으로 90° 회전하면

W → 동쪽으로 이동
D → 남쪽으로 이동

즉, 항상 플레이어가 바라보는 방향을 기준으로 '앞', '뒤', '왼쪽', '오른쪽'이 결정된다.

만약 transform.forward를 사용하지 않고 월드 좌표로 이동한다면,

플레이어가 동쪽을 보고 있어도 W를 누르면 계속 북쪽으로 가는 어색한 움직임이 된다.
))))))))))))))


* 카메라나 플레이어 회전에 맞는 이동을 쉽게 구현할 수 있다.

또한

```csharp
.normalized
```

를 사용하여 벡터의 길이를 1로 맞춘다.

#### 이유

대각선 이동 시

```
→ + ↑
```

의 길이는

```
√2 ≒ 1.414
```

가 되어 직선보다 약 **41% 빨라지는 문제**가 발생한다.

Normalize를 사용하면

모든 방향의 이동 속도를 동일하게 유지할 수 있다.

# 2. 목표 속도 계산

```csharp
Vector3 targetVel =
MoveDir * PlayerSpeed * stat.MoveSpeed;
```

### 기능

최종적으로 이동해야 하는 목표 속도를 계산한다.

여기서

* PlayerSpeed → 걷기 / 달리기 속도
* stat.MoveSpeed → 능력치 배율

을 곱하여 최종 속도를 만든다.

### 장점

속도 계산을 한 곳에서 처리하므로

* 버프
* 디버프
* 장비 효과

등을 쉽게 적용할 수 있다.


--------------------------------------------------------------------------

# 3. 현재 속도 가져오기

```csharp
Vector3 currentVel = Rb.linearVelocity;
```

### 기능

현재 Rigidbody가 실제로 움직이고 있는 속도를 가져온다.

이를 이용하여

현재 속도에서 목표 속도로 자연스럽게 변화시킨다.

--------------------------------------------------------------------------

# 4. 속도 보간(Lerp)

```csharp
Vector3 newVel = Vector3.Lerp(
    new Vector3(currentVel.x, 0, currentVel.z),
    targetVel,
    10f * Time.deltaTime
);
```

### 기능

현재 속도에서 목표 속도까지 한 번에 변경하지 않고

조금씩 가까워지도록 만든다.

즉

```
현재 속도

↓

점점 가속

↓

목표 속도
```

### 장점

즉시 속도를 변경하는 경우

```
0 → 8m/s
```

처럼 갑자기 움직여 조작감이 딱딱해진다.

Lerp를 사용하면

```
0

↓

2

↓

4

↓

6

↓

8
```

처럼 자연스럽게 가속된다.

이를 통해

* 움직임이 부드러워짐
* 급가속·급정지 감소
* 애니메이션과의 연결이 자연스러움
* 플레이 감각 향상

이라는 장점이 있다.

# 5. Y축 속도 유지

```csharp
Rb.linearVelocity = new Vector3(
    newVel.x,
    currentVel.y,
    newVel.z
);
```

### 기능

새로운 XZ 이동 속도만 적용하고

Y축 속도는 그대로 유지한다.

### 이유

점프 중에는

```
Y축 속도
```

가 중력과 점프에 의해 계속 변한다.

만약

```csharp
Rb.linearVelocity = newVel;
```

처럼 전체 속도를 덮어쓰면

Y축 속도가 0이 되어

* 점프가 끊기거나
* 낙하가 멈추는

문제가 발생한다.

따라서

```
XZ → 이동 시스템

Y → 물리 엔진
```

으로 역할을 분리하여

점프와 이동이 서로 영향을 주지 않도록 설계하였다.

# 전체 흐름

```text
플레이어 입력
      │
      ▼
이동 방향 계산
      │
      ▼
목표 속도 계산
      │
      ▼
현재 속도와 보간(Lerp)
      │
      ▼
XZ 속도만 Rigidbody에 적용
      │
      ▼
부드럽고 자연스러운 이동
```

### 포트폴리오에서 강조할 핵심

이 구조의 핵심은 **입력값을 즉시 속도로 적용하지 않고, 목표 속도를 계산한 뒤 현재 속도와 보간(Lerp)하여 Rigidbody에 반영한다는 점**이다. 또한 **Y축 속도는 유지하고 XZ축만 제어**하여 점프와 중력 같은 물리 효과를 보존하면서도, **부드러운 가속·감속과 일관된 이동 속도**를 구현했다는 점을 강조하면 설계 의도를 잘 전달할 수 있다.
