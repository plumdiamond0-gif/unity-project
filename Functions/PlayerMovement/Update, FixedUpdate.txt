입력(Update)과 물리(FixedUpdate)를 분리하는 이유 :

업데이트는 매 프레임마다 호출되서 컴퓨터 사양마다 호출 횟수 다름
픽스드업데이트는 무조건 1초에 50번 고정 호출됨
리지드바디를 포함한 물리엔진의 계산은 픽업 타이밍에 일어남.
업데이트에서 물리 처리하면 값을 여러번 덮어쓰거나 입력이 중간에 바뀌는 등 버그 발생
반면 입력은 미세한 입력까지 감지해서 받아야 하기 때문에 업데이트에서 처리
그래서 MovementX, MovementY같은 입력은 업데이트에서 받고 실제 물리 처리는 픽업에서 하는 것

-------------------------------------------------

Update()

Update()는 매 프레임마다 실행된다.
즉, 컴퓨터 성능에 따라 호출 횟수가 달라진다.

예를 들어

FPS	Update 호출 횟수
30 FPS	초당 30번
60 FPS	초당 60번
144 FPS	초당 144번

프레임이 많을수록 더 많이 실행된다.

그래서

transform.position += transform.forward * speed;

같은 코드를 Update에서 그대로 사용하면

144FPS에서는 엄청 빠르게 움직이고

30FPS에서는 느리게 움직이게 된다.

그래서 보통은

transform.position += transform.forward * speed * Time.deltaTime;

를 곱해서 프레임 차이를 보정한다.

-------------------------------------------------

FixedUpdate()

반면

FixedUpdate()는 물리 엔진 전용 업데이트다.

기본 설정에서는

0.02초마다 실행된다.

즉

1초 / 0.02

= 초당 50번

항상 50번 실행하려고 한다.

FPS가

30
60
120
240

이든 관계없이

물리 계산은 일정한 간격으로 이루어진다.

-------------------------------------------------

Rigidbody가 왜 FixedUpdate를 써야 할까?

Rigidbody 역시

물리 엔진이 관리한다.

즉

힘 계산

↓

충돌 계산

↓

속도 계산

↓

위치 계산

이 모든 과정이

FixedUpdate 타이밍에 일어난다

그래서

rb.linearVelocity = ...

나

rb.AddForce(...)

를 Update에서 계속 바꾸면

물리 계산과 타이밍이 맞지 않을 수 있다.

실제로 어떤 문제가 생기나?

-------------------------------------------------

그래서 입력은 Update에서 받는다

입력은 사람이 누르는 순간을 놓치면 안 된다.

예를 들어

60FPS

↓

0.016초마다 입력 확인

이라면

버튼을 짧게 눌러도 거의 놓치지 않는다.

하지만

FixedUpdate는

0.02초마다

만 확인하므로

아주 짧게 눌렀다가 떼면

아예 입력을 못 받을 수도 있다.

그래서

void Update()
{
    input = Input.GetAxis(...);
}

처럼 입력을 저장해 둔다.

그리고 이동은 FixedUpdate에서 한다
void FixedUpdate()
{
    rb.linearVelocity = input * speed;
}

이렇게 하면

물리 계산과 같은 타이밍에 움직이므로

충돌과 이동이 안정적으로 처리된다.

-------------------------------------------------

너의 코드도 이 구조다
void OnMove(InputValue inputValue)
{
    MovementX = value.x;
    MovementY = value.y;
}

여기서는 입력값만 저장한다.

그리고

void FixedUpdate()
{
    Vector3 moveDir = ...
    rb.linearVelocity = ...
}

에서 저장된 입력을 이용해 실제 이동을 수행한다.

즉, 입력 처리와 물리 처리를 분리한 구조다.
